# Snapshot correctness and Studio quality follow-up

Base: `ea00b2b776c99c0d7e788826c508336f21360480` (main after PR #22).
This change completes the dependency, snapshot, performance and quality-gate follow-ups from
the [initial review](2026-10-03-security-quality.md), including R12, R15 and R16.

## Runtime changes

Snapshot capture used a JSON round-trip that converted every untyped number to `float64` and
discarded serialization errors. For example, metadata containing integer `9007199254740993`
could be persisted as `9007199254740992`. Invalid metadata could produce incomplete snapshots.

- Capture, snapshot JSON decoding and restoration now retain `json.Number` when conversion to
  `float64` would change the numeric value after re-encoding. Values that round-trip exactly
  retain their existing `float64` representation.
- Precision is preserved in nested metadata and accumulated event data, including unsigned
  integers and long decimal fractions. Decimal comparison does not expand exponent magnitudes.
- The optional `instrumentation.SnapshotProvider` capability and `GetSnapshotWithError` helper
  return a complete snapshot or a contextual serialization error. Existing machine and executor
  interfaces remain compatible. Synchronous actions can use the helper with their arguments
  without reacquiring the owning machine's lock.
- Legacy `GetSnapshot()` logs capture errors and returns `nil`. Consumers must check that result.
  Metadata consumers must handle `json.Number` as well as `float64`.

See [runtime guidance](../runtime.md#snapshots) for usage and compatibility details.

## Dependency and quality changes

- Upgrade Vitest to 4.1.11 and migrate the mutation runner configuration. Stryker 10 supports
  this Vitest version; its initial instrumented test run was verified.
- Migrate the app from Tailwind 3 to Tailwind 4's Vite plugin, removing the old watcher/glob
  dependency chain that introduced the unpatched `braces` advisory. Regenerate the lockfile.
- The full workspace dependency audit reports **zero advisories**, including development
  dependencies, at the time of verification. This does not guarantee future advisories are absent.
- Replace placeholder lint commands with ESLint and enforce React hook ordering. Fix early
  returns in PropertiesModal and JsonIOModal that could change hook order across renders.
- Add a GitHub Actions workflow for Go build, vet, race tests and fuzz smoke; Studio frozen
  installation, lint, type checking, tests, Stryker dry-run, build and dependency audit.
  Actions use immutable commit pins and read-only repository permissions. Go setup selects
  the latest patch for the declared toolchain; Studio CI uses Node 24 and pnpm 10.11.0.

The Studio development workspace now requires Node 22 or later. Tailwind 4 requires modern
browsers; legacy browser support was not validated. The standalone app owns the Tailwind setup;
the published editor's React peer dependency remains unchanged.

## Performance changes and measurements

- Compare unchanged history sections by identity and changed sections by deep equality instead
  of serializing the entire graph twice per comparison. Undo checkpoints still clone their data.
- Group ordered transitions by source once during serialization, eliminating a full transition
  scan for each reality while preserving ordering.
- Load ELK asynchronously on the first layout request. Concurrent requests share its instance;
  a failed load can be retried. Existing automatic layout behavior is preserved, so apps requesting
  layout on mount still fetch the chunk then.

Production app build, compared with PR #22:

| Asset | Before | After |
| --- | ---: | ---: |
| Main JavaScript, minified | 2,283.01 kB | 802.13 kB |
| Main JavaScript, gzip | 676.52 kB | 225.09 kB |
| Separate ELK JavaScript, minified | Included above | 1,458.21 kB |
| CSS, minified | 45.52 kB | 68.40 kB |

The main JavaScript entry is about 65% smaller. ELK remains a large dependency; total downloaded
JavaScript is similar when layout is requested. Tailwind 4 increased the generated CSS size.

A local reducer benchmark used generated graphs with 256-character metadata per reality,
20 coalesced machine-ID edits, and the median of three runs with Node 24.19.0. Both versions
used their built CommonJS package on the same machine:

| Realities | Before | After |
| ---: | ---: | ---: |
| 100 | 6.41 ms | 0.40 ms |
| 1,000 | 49.40 ms | 2.96 ms |
| 5,000 | 250.12 ms | 21.39 ms |

These are measurements of that scenario, not a general latency guarantee. Checkpoint cloning
and other graph operations still have costs proportional to graph size.

## Validation

All checks below passed locally:

- Go build and vet; race-enabled tests with coverage across all 11 packages.
- Three native fuzz smoke targets, five seconds each, with two workers.
- Snapshot regressions for precise nested metadata, accumulated events, JSON persistence and
  restoration, detached data, serialization errors and callback capture without lock reentry.
- Frozen pnpm installation; workspace lint and type checking; **255 tests in 46 files**;
  all three package builds; dependency audit with zero advisories.
- Stryker dry-run: 16 tests passed with instrumented source. No full mutation campaign or
  mutation score is claimed.
- Chromium browser checks at 1440×900 and 390×844: rendered canvas, JSON export parsing,
  library opening/closing and auto layout. Production preview additionally fetched the
  separate ELK chunk successfully. No console or page errors occurred in these flows.
- Desktop baseline comparison preserved header geometry. Mobile rendering remains cramped
  in the existing header; this is not a responsive-layout redesign. Screenshots and command
  logs were retained in the review workspace.

The remaining callback ownership and asynchronous invoke lifecycle contracts described in the
initial review still apply. No production deployment or compatibility test against every
embedding application was performed.
